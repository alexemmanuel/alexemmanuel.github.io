Chain Stories — Collaborative Story-to-Screen Platform

PROTOTYPE
  • Turn-based collaborative storytelling — each writer adds exactly one line (180-char cap) to a shared chain framed as a Movie (60–240 min) or Series (configurable episodes/seasons), with Practice mode, twist words, and The End locked until ~85% of target runtime.
  • Live AI Story Analyst (Claude + local fallback), cinematic Watch mode, Premium invite-only chains with padlocks and join requests, story summaries after 10 lines, unique usernames, register/login with email recovery, and an intelligent Story Guide that answers real product questions (including missing timeline stories) and can offer safe storage repairs.
Frameworks: React Claude API Lucide Icons window.storage
Key OutcomeTurns collaborative writing into structured, watchable film/TV-style productions — with AI quality gates, runtime targets, archive lifecycle, unanimous delete petitions, invite-only Premium access, and auth that only counts visibility on registration (not reloads).
Application Proof
How It Was Built
Core Concept & Mechanics

A complete React web app for collaborative, one-line-at-a-time storytelling framed as film and TV production. Writers take turns adding exactly one line; no single author controls the whole plot. Movies target 60–240 minutes; series configure episode length, episodes per season, and seasons. “The End” unlocks at ~85% of estimated watch time.

Auth, Privacy & Access

Unique usernames (letters, numbers, underscore only — no spaces/symbols). Register/login with email recovery fields and hashed verification tokens; Google sign-in via Google Identity Services when a client ID is configured. Premium creators can publish invite-only chains: padlocked on the timeline for non-members, join-request flow, and owner approval in Story settings. Visibility increments on registration and real activity only — never on reload or invite-link opens.

Tools & Stack

React (hooks), Lucide icons, custom paper/ink CSS + cinema mode, Claude for line scoring and the Story Guide, browser window.storage with local profiles and shared chains/registry keys.

Key Features
  1. Formats & runtime — Movie or Series with progress bar; The End gated at ~85% of target.
  2. AI Story Analyst — Claude live scores 1–10 + verdict; local heuristic fallback outside the artifact.
  3. Watch mode — Timed cinematic player, likes, visibility scoring.
  4. Archives — 30-day inactivity; 5+ lines → archive (48h still on timeline); under 5 → permanent delete.
  5. Delete petition — Unanimous multi-writer delete; solo immediate.
  6. Invite-only Premium — Padlock, invite links, join requests, owner approve.
  7. Story summary — Dropdown synopsis after 10+ lines on accessible chains.
  8. Story Guide — Intelligent Q&A (why a story is missing, invites, archives) plus optional index repair + reload.
  9. Leaderboard — Shared writers registry; Premium CS badge; demo credits.
Key Challenge Solved — Narrative Quality Without Centralized Authorship

Challenge: Rotating authors can break genre tone or coherence on any single line.

Solution: AI Story Analyst scores and returns an editorial verdict before commit, without taking authorial control. Outside Claude.ai, a local heuristic keeps the gate available without shipping API keys in the browser.

Why a story may not appear on the timeline

Invite-only (padlocked) for non-members; archived after 30 days inactive; deleted if under 5 lines after 30 days; wrong tab (Active vs Archives); or not yet shared in the same storage context. Invite links and reloads do not grant visibility points.

Scope Note

Artifact build uses demo email confirmation and optional Google client ID for real GIS sign-in. Production requires a backend for secure email verification (time-limited hashed tokens, SMTP/provider) and server-side Google ID token verification. No real payments or MP4 encoding ship with the app.

The Lazy App — Multi-Service Aggregator

PROTOTYPE
  • Cross-references apartments, travel, delivery, dispatch, and professional services in one dashboard — matched to the user's own taste and budget.
  • Every listing shows its real service provider; selecting one redirects out to that provider's page to complete the actual booking or transaction.
Frameworks: React / Node.js Supabase (PostgreSQL) Claude Artifacts Serverless / Edge
Key OutcomeSolves fragmented service access — one dashboard replaces visiting multiple separate apps and sites, with an API normalization layer and SWR caching keeping it fast and cheap to run.
Application Proof
How It Was Built
Tools & Stack

Built with a React / Node.js frontend, using Supabase (PostgreSQL + Auth) as the backend database, rapidly prototyped by generating and refining modular UI components via Claude Artifacts.

Integrations

Integrated third-party REST APIs into a unified middleware layer to aggregate, parse, and render service data within a single user dashboard. Spans multiple categories — apartments, travel, delivery, dispatch, and professional services — letting users cross-reference options against their own taste and budget in one place. Each result surfaces its actual service provider, and selecting one redirects the user to that provider's site to complete the booking or transaction.

Role: Solo Full-Stack Developer

Managed the entire scope from API integration design and data transformation to UI components and serverless deployment.

Technical Decisions
  1. Unified API Normalization Layer — Built a client-side adapter pattern that transforms inconsistent third-party JSON responses into a single internal schema before passing data to UI components.
  2. Stale-While-Revalidate (SWR) Caching — Utilized aggressive client caching strategies to minimize unnecessary third-party API calls, drastically improving load speed and avoiding API rate limits.
  3. Zero-Compute Serverless Architecture — Kept infrastructure overhead near zero by deploying frontend assets to edge locations and relying on serverless edge functions for API routing.
Key Challenge Solved — Fragmented Service Access

Challenge: Users had to visit multiple separate websites and apps individually just to find and use the tools or services they needed — apartments, travel, delivery, dispatch, professional services — creating friction and wasted time across a fragmented set of destinations.

Solution: Built a single aggregator app that houses the functionality of multiple third-party services in one unified dashboard, letting users cross-reference options across categories against their own taste and budget to surface the best alternative. Each listing indicates its actual service provider, and clicking through redirects the user to that provider's page to complete the booking — the app handles discovery and comparison, not the transaction itself.

Debate & Poetry Arena — Dual-LLM Debate Platform

LIVE APPLICATION
  • Watch or host live, upcoming, past, and local debates — register by setting the topic, time, and scoring preferences in a few steps.
  • Powered by a dual-LLM debate engine (Claude 3.5 Sonnet vs. GPT-4o) with real-time guardrails, plus live poetry challenges for spoken-word performers.
Frameworks: Claude 3.5 Sonnet GPT-4o Python (FastAPI) WebSockets React / Next.js
Key OutcomeCombines a dual-LLM debate engine with a live event platform — turning debate and poetry into accessible, schedulable, spectator-friendly content instead of one-off text exchanges.
Application Proof
Live App
How It Was Built
LLM Engine & APIs

Powered by Anthropic Claude 3.5 Sonnet (selected for complex reasoning and structured rhythmic phrasing in poetry) working alongside OpenAI GPT-4o (configured as a fast, opposing debate persona).

Agent Orchestration & Communication

Built using a custom Python agentic workflow using state graphs rather than heavy third-party agent frameworks. The system coordinates turn-taking, dynamic response injection, and context passing sequentially via event-driven state nodes.

Frontend / Backend Stack

React / Next.js frontend with Tailwind CSS for dynamic turn visualization; Python (FastAPI) backend utilizing WebSockets for low-latency streaming of agent outputs.

Role: Lead AI Architect & Full-Stack Developer

Formulated the multi-agent orchestration architecture, prompt management system, real-time guardrails, and dynamic UI state sync.

Technical Decisions
  1. Sliding Context Window with Summarization — Preserved agent performance and lowered token costs by maintaining a rolling memory window that dynamically summarizes past rebuttal turns into compact system context.
  2. Intermediary Guardrail Node — Added a lightweight validation pass between turns to verify output format, catch repetitive phrasing, and enforce word-count boundaries before rendering responses to the client.
Key Challenge Solved — Debate & Poetry Accessibility

Challenge: Debates — live, upcoming, past, or local — and spoken-word poetry were scattered and hard to discover, leaving audiences with little consistent way to find and engage with them, and limiting how entertaining and far-reaching debate and poetry could actually be.

Solution: Built a platform where users log in, register for a debate by setting the time, topic, and scoring preferences, and can then watch live, upcoming, former, or local debates in one place — turning debate into an accessible, spectator-friendly experience. Extended the same platform to poetry with live poetry challenges, letting poets post and perform live online alongside the debate content.

Key Design Decision — Keeping Agents On-Topic & Distinct

Designed structural system prompts featuring explicit persona rules and objective constraints (e.g., "Address point B made by Opponent, limit rebuttal to two stanzas, and do not repeat arguments from Turn 1"). This prevented agents from losing topic context or slipping into passive agreement loops.

How It Was Built
Image Generation & Processing

Powered by Stable Diffusion model APIs for base image generation, combined with a custom Python pipeline using Pillow and OpenCV for image post-processing, trait compositing, and seed variation control.

Language & Framework Stack

Python (FastAPI) for the image generation pipeline and batch rendering backend; Node.js / React with Supabase for user management, asset metadata handling, and database storage.

Role: Full-Stack AI Systems Engineer

Designed and implemented the system end-to-end, from prompt engineering frameworks and batch rendering scripts to the full-stack user interface and database sync.

Technical Decisions
  1. Asynchronous Worker Queue — Implemented background task workers (Celery & Redis) to handle heavy model inference and batch image rendering without blocking HTTP thread execution.
  2. Automated Metadata Extraction — Built a pipeline step that auto-generates compliant Web3 metadata JSON schemas directly from batch render outputs before pushing assets to storage.
Key Challenge Solved — Visual Consistency Across Batches

Challenge: Maintaining coherent art style, line weight, and feature alignment across high-volume batch generations.

Solution: Used deterministic seed locking coupled with ControlNet conditioning and dynamic negative prompt injection to lock key stylistic traits across randomized asset outputs.
